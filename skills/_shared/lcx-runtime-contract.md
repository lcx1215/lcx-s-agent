# LCX Skill Runtime Contract

Use the current task, repository AGENTS.md and [architecture map](../../ops/architecture/LCX-SYSTEM-ARCHITECTURE.md) before historical receipts.

- Resolve the active Git checkout, entry, state/workspace root, model/tool adapters and owner from source, the nearest runbook and fresh process/receipt evidence. Do not infer them from a Skill's installation path. A global portable Skill used outside LCX must use that repository's owners.
- TypeScript owns routing, orchestration, safety, recovery and execution gates. The Central Agent Harness perceives governance, obtains a model proposal and records the gate/action/feedback cycle; it holds no execution authority.
- `gateway` and `serve` are explicit equal entries with different coverage. A finance scheduler and communication adapter require their own runtime evidence. Models, Qwen/MLX training, teachers and sidecars are optional profile-specific lanes.
- Use the lowest sufficient verification: focused source/diff, matching regression, required type/lint, then the relevant real entry only if the claim requires it. The problem radar routes to existing owners; a training-plan owner is not a whole-system prerequisite.
- Paper and Live are separate. A Skill grants no funds, credentials, orders, provider changes, memory writes or external sends. Retain the declared evidence, funding, risk, deduplication, reconciliation and execution gates.
- Report file presence, Skill selection/read, command execution, application, evaluation, weight learning, promotion, commit, runtime load, external binding and visible proof separately. Optional unsupported lanes degrade explicitly; do not invent success or block unrelated valid work.
