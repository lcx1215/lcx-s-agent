# 数据受阻模块的沙箱验证

当真实点时数据暂时不足时，可以用固定随机种子和显式合成场景验证策略合同、计算路径和失败闸门。沙箱的用途是发现实现错误、未来数据泄漏、成本遗漏和压力下错误放行；它不是历史回测、样本外检验、纸面交易或收益证明。

## 运行方式

实验包中的 `run_sandbox_strategy_tests.py` 使用固定种子 `20260910`，每次重建以下六个模块的 JSON 产物：

| 模块               | 沙箱关注点                               | 通过条件示例                                 |
| ------------------ | ---------------------------------------- | -------------------------------------------- |
| M03 宏观定价差     | 首发值、修订值、信号与成交时点、交易成本 | 只用首发值；能识别修订泄漏；非零方向才扣成本 |
| M04 暴露复制       | 训练/OOS切分、跟踪误差、风格突变         | 拟合不读未来；后段误差放大时重开风格漂移闸门 |
| M08 信用/可转债    | 债券、对冲、融资和借券撤回               | 压力亏损保留；违约或借券撤回阻断实施         |
| M09 指数事件       | 公告、确认、生效、撤回和抢跑             | 未确认或撤回不入场；抢跑和交易成本可见       |
| M10 尾部保护       | 保费、终值保护与慢跌/急跌路径            | 急跌保护兑现；慢跌仍体现保费拖累             |
| M11 波动率相对价值 | delta、gamma、vega、theta 与跳空         | 初始 delta 中性仍可因跳跃、波动率或时间损失  |

每个产物保留 `experiment_id`、参数、全部场景、检查结果和局限；`sandbox_summary.json` 汇总六个模块是否通过。脚本还会读取多方向实验清单，验证 D01–D28 的完整性、阶段计数、必填字段和实验收据引用，并写出 `multi_direction_sandbox_summary.json`。任何检查失败都使脚本退出非零，避免把半成品当作验证完成。

## 如何解释

- `all_checks_pass=true` 只表示本次合成场景满足预先写下的合同检查。
- 方向清单合同通过只表示研究范围登记和证据引用没有漏项；没有运行真实数据的方向仍保持其登记阶段。
- `stage` 保持 `method_only`，`validation_type` 为 `sandbox_contract` 或 `sandbox_contract_only`；不能据此进入 `research_candidate`、`paper_candidate` 或 `conditional_trade_candidate`。
- 沙箱不得填补真实来源缺口。真实研究仍需点时宏观发布、完整持仓、条款与融资、正式事件账本、期权曲面、成交可得性和独立复核。
- 若要晋级，必须另行提供同成本基线、无泄漏的真实或历史点时数据、样本外区间、稳健性、流动性和完整决策周期纸面记录。

产物位置：仓库相对的 `experiments/sandbox/` 沙箱目录（或由运行环境提供的等价研究根目录）。它们是研究证据的附录，不是当前持仓、经纪商权限或执行请求。
